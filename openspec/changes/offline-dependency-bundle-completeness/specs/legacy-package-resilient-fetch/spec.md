## ADDED Requirements

### Requirement: 老旧包弹性采集
当目标依赖无可用 wheel 时，系统 MUST 提供弹性采集路径以尽可能获取对应源码分发包，并保持可追溯性。

#### Scenario: wheel 不可用时采集源码包
- **GIVEN** 目标依赖在目标环境下没有可用 wheel
- **WHEN** 系统进入源码采集阶段
- **THEN** 系统 MUST 尝试获取该依赖的源码分发包并记录来源
- **THEN** 采集结果 MUST 写入源码清单与处理指引

#### Scenario: 老旧包构建元数据失败时保留可用产物
- **GIVEN** 某老旧包在本地构建元数据阶段失败
- **WHEN** 系统存在替代采集路径
- **THEN** 系统 MUST 优先保留可直接下载的产物并避免整体任务直接中断
- **THEN** 报告 MUST 标注该包需要私网侧手工构建或替代版本

### Requirement: 回退阶段一致性约束
系统 MUST 保证回退阶段不会引入与目标环境不一致的产物，并输出阶段化证据。

#### Scenario: 回退阶段禁止主机平台污染
- **GIVEN** 当前执行机与目标平台不一致
- **WHEN** 系统执行回退采集
- **THEN** 系统 MUST 不将仅适配执行机平台的 wheel 标记为目标可用
- **THEN** 覆盖报告 MUST 明确标注该包是否仅完成源码采集

#### Scenario: 两阶段失败保留完整证据
- **GIVEN** wheel 阶段与源码采集阶段均失败
- **WHEN** 系统返回失败结果
- **THEN** 错误信息 MUST 同时包含两个阶段的摘要
- **THEN** 报告 MUST 输出下一步建议（版本替换、目标降级或手工构建）
